# v1.0.0

The first release of this fork of [Kubernetes Commander](https://github.com/sttts/kc). kc is a two-panel Kubernetes TUI in the style of Midnight Commander, built on controller-runtime informers, so the lists stay live.

## Install

```bash
brew install --cask stokaro/kc/kc
```

Or download an archive from the [release page](https://github.com/stokaro/kc/releases/tag/v1.0.0). Linux and macOS, amd64 and arm64. `kc_checksums.txt` is signed with cosign; see the README for `cosign verify-blob`.

The macOS binaries are not notarized. If macOS refuses to start a kc you downloaded with a browser, remove the quarantine attribute: `xattr -d com.apple.quarantine kc`. Homebrew does this for you.

## What it does

- Two panels that browse contexts, namespaces, resource types, objects and their children (Deployments to ReplicaSets to pods to containers, Services to EndpointSlices, ConfigMap and Secret keys), with an mc-style menu bar, function-key bar and a terminal underneath.
- The second panel can follow the first in Describe, Manifest, Logs or Info mode. Info shows CPU, memory, pod and disk use with history.
- A full-screen dashboard (`C-x g`, `kc dashboard`) for a namespace, node, workload or pod: CPU and memory against requests and limits, from metrics-server or Prometheus, with the Kubernetes Events on the same time axis. In iTerm2 3.7+, kitty and Ghostty the charts are drawn as images; elsewhere in text.
- Logs: streaming with reconnects, merged logs of a workload, JSON lines as fields, filters, and logs around an Event or a chosen time window.
- The cluster overview and a diagnosis of broken objects, with the reason for each finding.
- Actions that ask first and show the kubectl equivalent: scale, restart, roll back, drain, delete, edit. Read-only mode refuses them.
- Files: browse a container's filesystem, view large files in pages, copy between local folders and containers.
- Helm releases with values, manifests and history, without the `helm` binary.
- The Work profile lists the resource types most people use; the rest are one row away. Named visibility profiles can be bound to a kube context.
- `kc get ...` and `kc logs ...` accept kubectl syntax and open the matching folder.

Press `F1` anywhere for help. The README and the [screenshot catalog](https://github.com/stokaro/kc/blob/v1.0.0/screenshots/README.md) show more.

Configuration lives in `~/.kc/config.yaml`; `config-default.yaml` in the repository lists every setting with its default.
